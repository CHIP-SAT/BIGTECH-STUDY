# 4장 해시 테이블

<aside>

**해시 테이블(hash table)**은 **키(key)**와 **값(value)**의 대응으로 이루어진 표와 같은 형태의 자료구조이다.
데이터는 버킷(bucket)에 저장되어 있다.
버킷은 여러 개가 존재하며, 여러 버킷들은 배열을 형성한다. 해시 함수는 키를 인자로 활용해 인덱스를 반환하고 이는 버킷 배열의 인덱스에 해당한다.
빠른 검색 속도가 장점이다.

![image.png](attachment:e7479086-a451-4240-b2aa-6be9ee28dd70:image.png)

## 해시 함수

**해시 함수(hash function)**는 임의의 길이를 지닌 데이터를 고정된 길이의 데이터로 변환하는 단방향 함수이다.
해시 함수의 연산 방법을 해시 알고리즘이라고 한다.
대표적인 해시 알고리즘은 SHA-1, SHA-256, SHA-512, SHA3, HMAC 등이 있다.

## 해시 충돌

서로 다른 키에 대해 같은 해시 값이 대응되는 상황을 **해시 충돌(hash collision)**이라고 한다.
해시 충돌을 해결하기 위한 방법으로 체이닝과 개방 주소법이 있다.

**체이닝(chaining)**은 충돌이 발생한 데이터를 연결 리스트로 추가하는 방법이다.
이는 연결 리시트와 다를 바 없는 O(n)의 시간이 걸린다.

![image.png](attachment:b8df66c0-6061-466c-be73-91389cf46bc0:image.png)

**개방 주소법(open addressing)**은 충돌이 발생했을 때, 충돌이 발생한 버킷의 인덱스가 아닌 다른 인덱스에 데이터를 저장하는 방법이다.
충돌이 발생했을 때 비어 있는 다른 버킷의 인덱스를 찾는 과정을 **조사(probe)**한다고 표현한다.

**선형 조사법(linear probing)**은 충돌이 발생했을 때 충돌이 발생한 인덱스의 다음 인덱스부터 순차적으로 가용한 인덱스를 찾는 방법이다. 이는 충돌이 발생하는 인덱스 인근에 충돌이 발생한 데이터가 몰려 저장되는 데이터의 **군집화(clustering)** 현상이 발생하여 오랜 순차 탐색 이필요해 성능 악화로 이어질 수 있다.

![image.png](attachment:c63d50c9-bcb4-4e16-8e21-23f32d97fd53:image.png)

**이차 조사법(quadratic probing)**은 충돌이 발생한 인덱스에서 제곱수만큼 떨어진 거리에 위치한 인덱스를 찾는 방법이다. 선형 조사법과 비교해 데이터 군집화 문제는 완화할 수 있지만, 해결하는 근본적인 방법이라고는 할 수 없다.

해시 충돌의 다른 해결 방법으로 **이중 해싱(double hashing)**이 있다.
2개의 해시 함수를 사용하는 방법으로 충돌이 발생했을 때 다른 해시 함수에 대한 해시 값만큼 떨어진 거리에 위치한 인덱스를 찾는 방법이다.
